# Agent instructions

Instructions for AI coding agents (Claude Code, Codex, OpenCode, Copilot and others) working in
this repository. People are welcome to read them too. What the catalog is for is in the
[README](README.md).

## What this repository is

`agentic-marketplace` is the plugin marketplace for the agent skills of cbs open source tools. It lists
plugins; it holds no skills. Each plugin is the root of a tool's repository, with an Agent Plugins
1.0 `plugin.json` and Agent Skills in `skills/<name>/SKILL.md`.

| Path | What it is |
| --- | --- |
| `.agents/plugins/marketplace.json` | The catalog. Edit this file. Codex reads it. |
| `.claude-plugin/marketplace.json` | Generated by `npm run sync`. Claude Code and Copilot CLI read it. |
| `scripts/lib.js` | Checks for the catalog, `plugin.json` and `SKILL.md`. |
| `scripts/sync-manifests.js` | Writes `.claude-plugin/marketplace.json` from the catalog. |
| `scripts/check-sources.js` | Clones each listed repository and checks it. |
| `test/` | `node:test` suite; `test/fixtures` holds a valid and a broken plugin repository. |

## Commands

| What | Command |
| --- | --- |
| Whole suite (always run this) | `npm test` |
| Regenerate the Claude Code and Copilot marketplace | `npm run sync` |
| Check the listed repositories (needs network) | `npm run check:sources` |
| Check one listed repository | `npm run check:sources -- eslint-plugin-cds` |

There are no dependencies, no build, and no linter or formatter. Match the style of the
surrounding code: scripts with double quotes and semicolons, tests with single quotes and no
semicolons.

## Rules

- **Plugin names and the catalog name are public.** Users install `<plugin>@cbs-consulting`.
  Renaming a plugin or the catalog breaks their installs; say so in the changelog.
- **Edit only `.agents/plugins/marketplace.json`,** then run `npm run sync`. The tests fail when
  `.claude-plugin/marketplace.json` is stale.
- **Stay agent-agnostic.** Use the open formats (Agent Skills, Agent Plugins, `marketplace.json`).
  Don't add fields or files that only one agent understands unless every other agent ignores them,
  and document each agent's install steps in the README.
- **Skills live in the tools' repositories.** Don't copy a skill into this repository.
- **Every plugin has a row in the README;** `test/catalog.test.js` checks this.
- **Every pull request adds a line under `## Unreleased` in `CHANGELOG.md`**, written for users,
  or gets the label `no changelog`.
- **CI runs on Windows, macOS and Linux.** Use `path`, don't assume a POSIX shell in tests.
- **GitHub Actions are pinned by commit SHA.** Don't add a dependency without asking; there are
  none.

## Conventions

- **Writing style.** Docs, comments, messages and changelog use short, plain sentences in the
  present tense and say what happens for the user. Check messages say what is wrong and how to fix
  it. Docstrings are one line where possible.
- **Commits and PRs.** The subject is an imperative sentence in plain words; the body says why,
  and the PR fills in `.github/pull_request_template.md`.

## Don'ts

- Don't skip, disable or loosen a test to make CI pass.
- Don't run the Release workflow or push tags.
- Don't commit `node_modules/`, `*.tgz` or `.env*`.
